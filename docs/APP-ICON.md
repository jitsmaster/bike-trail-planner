# App icon: a cyclist on a trail

The app used to ship the stock Android robot: `AndroidManifest.xml` had no `android:icon`, and there
was no `mipmap` directory at all. It now ships a purpose-drawn icon whose geometry lives in exactly
one place, `tools/make_icon.py`.

## 1. The design

A cyclist riding along a trail, seen from the side, as a near-silhouette on the app's own blue.

Everything is built to survive 48 dp, which is the size the launcher actually draws:

* **Two wheels, drawn as rings, not discs.** Each wheel is a ring of outer radius 11.8 and hole
  radius 7.4 (in 108-space), so even at 48 px the hole is 6.6 px across and the wheel reads as a
  wheel. There is deliberately **no hub dot**: a dot in the middle is exactly what turns a wheel
  back into a blob at small sizes.
* **The frame stops on the rim, never at the hub.** Every frame member ends at a point `rim_r` from
  the wheel centre (`_rim()` in the generator). The round line cap is 2.1 wide, so it stays inside
  the ring band and the hole stays empty. Measured: both wheels still enclose background at 48 px.
* **The rider is a mass, not a stick.** The torso is a filled quad, the head a filled circle of
  radius 5.6, with an arm reaching down-forward to the handlebar and a bent leg on the crank.
* **The trail is a spline, not a straight line**: five control points sampled through a Catmull-Rom
  spline (the same sampled polyline is what both the vector and the raster draw), rising gently from
  left to right, with the tyres sitting on it.
* **A diagonal gradient background** in the app's two blues, so the icon does not look out of place
  beside the always-light UI (D19).

Regenerating the preview: `docs/app-icon-preview.png` is a 512x512 render of the icon, the same icon
behind a circular launcher mask, and behind a rounded-square mask.

## 2. The palette

Every colour is already an app colour; the two new names live in
`app/src/main/res/values/colors.xml` and are asserted against this table by the generator, so the
icon cannot drift from the palette.

| Role | Value | Where it comes from |
| --- | --- | --- |
| Background gradient start | `#1A73E8` | `colors.xml` `primary_light` = `Theme.kt` `MapsPalette.primary` |
| Background gradient end | `#174EA6` | `colors.xml` `ic_launcher_background_end` = `MapsPalette.onPrimaryContainer` |
| Cyclist (all art) | `#FFFFFF` | `colors.xml` `surface_light` = `MapsPalette.surface` |
| Trail | `#D2E3FC` | `colors.xml` `ic_launcher_trail` = `MapsPalette.primaryContainer` |

The trail is that pale blue on purpose: it has to be legible as "a path" without competing with the
white cyclist, which is the shape the eye must read first.

## 3. Safe-zone arithmetic

An adaptive icon is a 108x108 dp layer. The launcher masks the outer part away, so the region that
is *guaranteed* to be visible is the central 66x66 dp, i.e. `x, y` in `[21, 87]`. The mask also
slides under parallax, so nothing that matters may touch that edge.

The generator keeps the whole artwork inside a stricter box, `x, y` in `[23, 85]`, so that
antialiasing cannot push ink out of the real safe zone. The authored artwork measures
**x 23.20 .. 84.80, y 27.00 .. 81.90** - inside the strict box in every direction.

Scaled to each raster size, the guaranteed-visible band is `[21, 87] / 108 * size`, and the shipped
PNGs are checked against exactly that:

| bucket | size | allowed pixel indices | measured ink bbox | verdict |
| --- | --- | --- | --- | --- |
| mdpi | 48 px | 10..37 | `(10,12)-(37,36)` | inside, both square and round |
| hdpi | 72 px | 14..57 | `(16,18)-(55,54)` | inside, both |
| xhdpi | 96 px | 19..76 | `(21,24)-(74,72)` | inside, both |
| xxhdpi | 144 px | 28..115 | `(32,36)-(111,109)` | inside, both |
| xxxhdpi | 192 px | 38..153 | `(43,48)-(149,145)` | inside, both |

The square and the circular PNG are the same art, so they measure identically; the full
per-file table, with ink pixels and coverage, is in section 6.

Vertical space: the trail's lowest ink is y = 81.9, the head's highest is y = 27.0, so the art uses
54.9 of the 66 guaranteed dp and sits optically centred (7.0 dp above, 5.1 dp below).

## 4. Files

Generated by `tools/make_icon.py` - do not hand-edit:

| File | What it is |
| --- | --- |
| `app/src/main/res/drawable/ic_launcher_foreground.xml` | VectorDrawable, 108x108 viewport, cyclist + trail |
| `app/src/main/res/drawable/ic_launcher_background.xml` | VectorDrawable, one corner-to-corner gradient |
| `app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml` | adaptive-icon: background + foreground |
| `app/src/main/res/mipmap-anydpi-v26/ic_launcher_round.xml` | same, for launchers that ask for a round icon |
| `app/src/main/res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher.png` | legacy fallbacks, 48/72/96/144/192 px |
| `app/src/main/res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher_round.png` | the same, masked to a circle |
| `docs/app-icon-preview.png` | 512 px preview: plain, circular mask, rounded-square mask |
| `docs/phone-evidence/app-icon-on-launcher-2026-09-16.png` | the real home screen on the phone |

Hand-edited, so they are checked by the generator instead:

* `app/src/main/AndroidManifest.xml` - `android:icon="@mipmap/ic_launcher"` and
  `android:roundIcon="@mipmap/ic_launcher_round"` on `<application>`.
* `app/src/main/res/values/colors.xml` - the two extra colour names in section 2.

`minSdk` is 26, so every device that can run the app inflates the adaptive icon; the PNGs are only a
fallback for launchers that ask for a legacy bitmap.

## 5. Regenerate

```sh
python3 tools/make_icon.py
```

It writes every file above and then verifies its own output, exiting non-zero on any failure. The
only dependency is Pillow, so the plain system `python3` is enough.
